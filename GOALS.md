# Learning Goals

This file turns the 24-month roadmap into outcomes I can check. I will measure progress by what I can explain, build, test, and document—not by the number of hours studied or pages read.

**Planning note:** Month 1 begins when I start following this roadmap consistently. The month ranges are targets, not hard deadlines. If a skill is not secure yet, I will extend the phase and update my plan instead of skipping the fundamentals.

## My 24-month outcome

By the end of Month 24, my goal is to have a public, documented portfolio that demonstrates:

- [ ] Confident Python fundamentals and the ability to build small programs without copying a complete solution.
- [ ] A responsive technical blog built with semantic HTML, organized CSS, and a useful JavaScript feature.
- [ ] Working knowledge of common data structures, algorithm analysis, and basic problem-solving patterns.
- [ ] Practical SQL and a basic understanding of operating systems and networking.
- [ ] At least one Python backend application connected to a database, with documented API endpoints and automated tests.
- [ ] At least one project deployed online, with a documented setup, automated checks, and clear limitations.
- [ ] A GitHub profile with readable READMEs, meaningful commit history, and links to the main projects.

## Goals by phase

### Phase 0 — Learning workflow and GitHub
**Target:** Month 1, first 1–2 weeks (alongside Phase 1)

- [ ] Keep the README, ROADMAP.md, GOALS.md, and PROGRESS.md updated.
- [ ] Make at least one small, meaningful documentation commit.
- [ ] Explain what a repository, commit, branch, and README are in my own words.
- [ ] Avoid committing passwords, API keys, private logs, or other sensitive information.

**Evidence:** This repository has working navigation, clear documentation, and a small commit that I can explain.

### Phase 1 — Python foundations
**Target:** Months 1–5

- [ ] Practise variables, conditions, loops, functions, collections, file handling, exceptions, modules, and introductory classes.
- [ ] Solve small practice problems by writing my own first attempt, then use errors and tests to improve it.
- [ ] Build a CLI Task Manager that can add, list, complete, and remove tasks, and save them to a file.
- [ ] Build a Hardware/Flight Log Parser using a sample or safely shareable log; extract chosen fields and produce a readable summary.
- [ ] Add a README with setup and usage instructions to at least one project.
- [ ] Explain the main functions and debugging choices in my own words.

**Evidence:** Working code, a few meaningful test cases, README instructions, and commits showing development progress.

### Phase 2 — Web foundations and technical blog
**Target:** Months 6–8

- [ ] Build with semantic HTML and a separate CSS stylesheet.
- [ ] Use responsive layout techniques and test the website at mobile and desktop widths.
- [ ] Add at least one meaningful JavaScript feature, such as a menu interaction, a filter, or form validation.
- [ ] Check links, images, headings, keyboard usability, and common layout issues with browser developer tools.
- [ ] Publish the website if a suitable hosting option is available.
- [ ] Document the site's structure and the feature I implemented.

**Evidence:** A working repository for the site, screenshots or a live URL when published, and a README explaining the implementation.

### Phase 3 — Data structures and algorithms
**Target:** Months 9–12

- [ ] Explain Big-O notation and compare the basic time and space trade-offs of common data structures.
- [ ] Implement and test examples of stacks, queues, searching, sorting, and a hash-map-like structure.
- [ ] Build a pathfinding project using BFS; extend it with Dijkstra's algorithm when ready.
- [ ] Solve beginner-level problems independently and write down the approach, complexity, and edge cases.
- [ ] Attempt a Huffman-coding experiment only after trees and priority queues make sense.

**Evidence:** Small tested implementations, problem-solving notes, and at least one documented algorithm project. Huffman coding is an extension goal, not a blocker.

### Phase 4 — Computer Science fundamentals and databases
**Target:** Months 13–15

- [ ] Create a relational schema for a small inventory-management scenario, including appropriate keys and relationships.
- [ ] Write and test SQL queries using filters, joins, grouping, and aggregation.
- [ ] Explain, at a basic level, processes versus threads, virtual memory, DNS, TCP, and HTTP request/response.
- [ ] Complete one small script or command-line experiment and document what it taught me.
- [ ] Write a short note tracing what happens from entering a URL to receiving a web page.

**Evidence:** A schema diagram or documented schema, a SQL file with sample queries, and concise notes backed by small experiments.

### Phase 5 — Backend development and full-stack applications
**Target:** Months 16–20

- [ ] Choose one Python framework—Django or FastAPI—and build with it before considering another.
- [ ] Build an Inventory API that can create, list, retrieve, update, and delete records.
- [ ] Connect the application to a database and document how to configure it locally.
- [ ] Validate input and return clear success and error responses.
- [ ] Write automated tests for important normal cases and failure cases.
- [ ] Explain the main request-to-database flow and keep secrets out of source control.

**Evidence:** A working API, documented endpoints, database setup instructions, automated tests, and an understandable README.

### Phase 6 — Quality, deployment, and operations
**Target:** Months 21–24

- [ ] Add or improve unit and integration tests for a portfolio project.
- [ ] Create a GitHub Actions workflow that runs relevant automated checks.
- [ ] Package the backend project with Docker when its setup is stable.
- [ ] Deploy at least one suitable project and document its URL, configuration, limitations, and basic troubleshooting steps.
- [ ] Explain how to install, test, run, and deploy the project from a fresh checkout.
- [ ] Review the portfolio and improve unclear READMEs and unfinished project links.

**Evidence:** A deployed project, a passing automated workflow, repeatable setup instructions, and a portfolio that is easy for another person to review.

## Weekly learning routine

At the beginning of each week, choose a small target that fits around my other responsibilities.

- [ ] Select one primary topic or skill for the week.
- [ ] Practise it by writing code or changing the website—not only watching or reading.
- [ ] Save one short note explaining what I learned or what blocked me.
- [ ] Make a meaningful Git commit when I have a useful change to save.
- [ ] At the end of the week, record the evidence and choose the next action in PROGRESS.md.

A missed week does not mean the plan has failed. I will restart with a small task and keep the goals realistic.

## Rules for deciding a goal is complete

I will mark a goal complete only when I can point to evidence. Depending on the goal, evidence can be working code, test results, a clear explanation in my own words, a documented experiment, or a deployed feature.

I will avoid copying complete solutions without understanding them. It is acceptable to use documentation, tutorials, and AI as learning support, but I should be able to explain, modify, and debug the result independently before treating the skill as learned.

## Scope control

- Python is my primary programming language during the core roadmap.
- I will continue improving my technical blog alongside the main sequence when workload allows.
- I will not try to learn Python backend development and advanced Java at the same time during the foundation stages.
- Java and machine learning are optional specialization tracks after the core goals, unless I deliberately revise the roadmap based on demonstrated progress.
